# ที่อยู่ของลิงก์ GPS ไม่เคยขึ้น — เราทำให้ตัวเองโดน Nominatim จำกัดอัตรา — 2026-10-17

อาการ: ช่องที่อยู่ของลิงก์ GPS ในหน้า "ตารางเวลาทำงาน" แสดงแต่พิกัดดิบ ไม่เคยกลายเป็นชื่อสถานที่ ·
console เต็มไปด้วยคู่ error "CORS blocked" + "net::ERR_FAILED" ของ
`https://nominatim.openstreetmap.org/reverse`

> **คำเตือนถึงคนที่อ่านทีหลัง:** ไฟล์นี้เคยสรุปว่า "Nominatim ปฏิเสธ IP ของออฟฟิศ" ซึ่ง**ผิด** ·
> ข้อสรุปนั้นมาจากการวัดครั้งเดียวในนาทีที่เรายังถูกจำกัดอัตราอยู่ · การวัดครั้งที่สองในวันเดียวกัน
> พลิกข้อสรุป และเหตุผลที่มันพลิกสำคัญกว่าข้อสรุปเอง — อยู่ในหัวข้อ "สองการวัด" ด้านล่าง

## ที่เห็นเป็น CORS error ไม่ใช่เรื่อง CORS

ยืนยันด้วย `curl` จากเครื่องออฟฟิศ ซึ่งเห็น HTTP status จริง — สิ่งที่เบราว์เซอร์ไม่ยอมแสดง:

- `/reverse` ตอบ **HTTP 429 Too many requests**
- หน้า error 429 **ไม่ส่ง header `Access-Control-Allow-Origin`** (หน้า 200 ส่ง) ⇒ เบราว์เซอร์บล็อก
  แล้วรายงานว่าเป็นเรื่อง CORS · **อ่าน error ตามตัวอักษรแล้วจะแก้ผิดจุด**
- ใส่ `User-Agent` ระบุตัวตนแล้วยัง 429 ⇒ ไม่ใช่เพราะขาด UA (และ `fetch()` ตั้ง header นี้ไม่ได้อยู่แล้ว)
- `attendance/index.html` อนุญาต `https://nominatim.openstreetmap.org` ใน `connect-src`
  อยู่แล้วตั้งแต่ 2026-09-24 ⇒ **ไม่ใช่ปัญหา CSP ไม่ต้องแตะ CSP**
- `/status.php` ตอบ 200 จาก IP เดียวกันในนาทีเดียวกัน ⇒ บริการไม่ได้ล่ม

## สองการวัด และทำไมครั้งที่สองถึงพลิกข้อสรุป

| เวลา | สภาพของแอป | ผลของ `/reverse` จากออฟฟิศ |
|---|---|---|
| ~10:12–11:15 | แอปกำลังยิงรัวจากทุกเบราว์เซอร์ที่เปิดหน้านี้ | **429** เกือบทุกใบ (มีหลุดมา 200 บ้าง — 3 จาก 5 พิกัดเคยได้ที่อยู่จริง) |
| 11:45 | หยุดยิงไปแล้วราว 40 นาที | **200 ทั้ง 3 พิกัด** พร้อม `display_name` ภาษาไทยจริง |

ตัวอย่างคำตอบตอน 11:45 ของพิกัดออฟฟิศ `13.724704,100.550299`:
`บ้านพระรามสี่ พลัส, แขวงลุมพินี, เขตปทุมวัน, กรุงเทพมหานคร, 10330, ประเทศไทย`

⇒ **IP ของออฟฟิศไม่ได้ถูกแบน** การจำกัดอัตราเป็นผลจากพฤติกรรมของแอปเอง และมันคลายเมื่อหยุดยิง ·
ที่สำคัญกว่านั้น มันเป็น**วงจรที่เลี้ยงตัวเอง**: ถูกจำกัด → คำขอล้มเหลว → cache ไม่จำเคสล้ม →
render ถัดไปยิงใหม่ทั้งหมด → ยิ่งถูกจำกัด

**บทเรียนของการวัด:** ครั้งแรกผมวัดในขณะที่ตัวแปรที่ต้องการวัด (ปริมาณคำขอของเราเอง) ยังเปิดอยู่
แล้วสรุปสาเหตุจากสภาพที่ตัวเองสร้างขึ้น · การวัดซ้ำหลังจากหยุดสิ่งที่เราควบคุมได้ คือสิ่งที่แยก
"เขาปฏิเสธเรา" ออกจาก "เราทำตัวเอง"

## บั๊กในโค้ด

`reverseGeocode()` เขียน `geoCache[key]` อยู่ **ข้างใน `.then()`** ส่วน `.catch()` เรียก callback
กลับไปเฉยๆ โดยไม่บันทึกว่าพิกัดนี้เพิ่งล้มเหลว ⇒ เมื่อคำขอถูกปฏิเสธ cache จึงว่างตลอดกาล
และทุกการ render ก็เริ่มนับหนึ่งใหม่

และ `r.json()` ถูกเรียกกับ response ทุกชนิด ⇒ หน้า 429 (เป็น HTML) นับเป็น network error
เพราะ parse พัง ไม่ใช่เพราะอ่าน status ⇒ โค้ดไม่เคย "รู้" ว่าโดน 429

วัดบนเว็บจริง (ล็อกอิน role `md` ด้วยบัญชี QA ที่เจ้าของให้ไว้ · ครอบ `window.fetch` เพื่อนับ):

- ลิงก์ GPS ใน DOM **12 ลิงก์** (แถวตารางเดสก์ท็อปกับการ์ดมือถือถูก render ทั้งคู่เสมอ)
- พิกัดไม่ซ้ำ (ปัด 4 ตำแหน่ง ≈ 11 ม.) **5 พิกัด** → ยิงจริง **5 คำขอต่อ render**
  ⇒ การ dedupe ต่อ render *ทำงานถูกอยู่แล้ว* (แก้ไว้ตั้งแต่ 2026-08-17) ไม่ใช่จุดที่พัง
- ปล่อยหน้าไว้เฉยๆ 10 วินาที: **+0** ⇒ ไม่มี timer หรือ WS ที่ re-render เอง
- `renderAttendanceTable()` ซ้ำ: **+5 ทุกครั้ง** URL เดิมทั้ง 5 และ cache ยังว่าง

⇒ ตัวคูณคือ **จำนวนครั้งที่ re-render × จำนวนพิกัดไม่ซ้ำ** ไม่ใช่การยิงพร้อมกันรอบเดียว ·
หน้านี้ re-render บ่อยมาก: สลับเดือน สลับพนักงาน สลับภาษา (`applyLanguage()` เรียก `navigateTo()`)
และทุกครั้งที่กลับเข้าหน้า

### จุดที่คิวเดิมไม่คุม

- `geocodeTableGpsLinks()` หน่วงด้วย `setTimeout(..., i * 1100)` โดย `i` เริ่มนับ 0 ใหม่ทุกครั้งที่
  ถูกเรียก ⇒ render สองรอบห่างกัน 1 วินาที คำขอรอบใหม่ไปทับเวลาของรอบเก่า
- ป๊อปอัป Details (`renderGpsEntry()`) เรียก `reverseGeocode()` **ทันที** ไม่ผ่านการหน่วงใดๆ

⇒ การหน่วงที่กระจายตามจุดเรียก รวมเป็น **คิวเดียวของทั้งแอป** ได้ประโยชน์กว่า

## สิ่งที่แก้ (build 137)

- **คิวเดียวของทั้งแอป** เว้น `GEO_MIN_INTERVAL_MS` = 1100 ms ต่อคำขอ ตามนโยบาย 1 คำขอ/วินาที
- **พิกัดเดียวถูกถามครั้งเดียว** — จำทั้งคำตอบและการถูกปฏิเสธ และพิกัดที่กำลังรออยู่จะเก็บ callback
  เพิ่มแทนการยิงซ้ำ (render สองรอบห่างกัน 200 ms เคยยิงซ้ำตรงนี้)
- **cache อยู่ข้ามการรีเฟรช** — `localStorage` คีย์ `ta_geocache_v1` คีย์ย่อยเป็นพิกัดปัด 5 ตำแหน่ง ·
  ที่อยู่หมดอายุ 30 วัน · การถูกปฏิเสธหมดอายุ 10 นาที (**ไม่จำตลอดกาล** ไม่งั้นโดนจำกัดครั้งเดียว
  แล้วที่อยู่นั้นจะไม่มีวันขึ้นอีก) · เก็บไม่เกิน 300 รายการ ตัดอันเก่าสุดทิ้ง · **ทุกการอ่าน/เขียน
  ห่อ try/catch** และทำงานได้เมื่อว่าง เสีย หรือใช้ไม่ได้ (private window / ปิด site data / quota เต็ม)
- ถูกปฏิเสธติดกัน 3 ครั้ง → **พักคิว 5 นาที** แล้วให้โอกาสใหม่ · 200 ที่ไม่มี `display_name`
  ไม่นับเป็นการถูกปฏิเสธ เพราะบริการตอบแล้ว
- อ่าน `r.ok` ก่อน `r.json()` ⇒ โค้ดรู้ว่าโดน 429 จริงๆ ไม่ใช่เดาจาก parse ที่พัง
- เมื่อแปลงไม่ได้ หน้าจอ**บอกตรงๆ** 3 ภาษา: `พิกัด …` / `coords …` / `座標 …`
  พร้อม tooltip บอกเหตุผล — ไม่ปล่อยเป็นตัวเลขเปล่า และไม่ค้างคำว่า "กำลังโหลด..."

## ตรวจอย่างไร และสิ่งที่ยัง **ไม่ได้** ตรวจ

**ตรวจแล้ว:**

- `tests/geocode-queue-cache.test.js` (ใหม่) — ดึงโค้ดจาก `app.js` จริงมารันใน `vm` ตามแบบของ
  `tests/checkout-review.test.js` · 12 เคส: คำขอหนึ่งใบต่อหนึ่งพิกัดถึงจะมีคนถามซ้อนกัน ·
  เว้นระยะตามนโยบาย · render รอบสองไม่ยิงเลย · **cache รอดข้ามการรีเฟรช** (sandbox ใหม่ที่ใช้
  storage เดิม ยิง 0 คำขอ) · การถูกปฏิเสธถูกจำ และ**หมดอายุ** · พักคิวหลังถูกปฏิเสธติดกัน ·
  200 ที่ไม่มีชื่อสถานที่ไม่นับเป็นการถูกปฏิเสธ · localStorage ที่ throw ทั้งอ่านและเขียนยังทำงานได้ ·
  ข้อมูลเสียใน storage ไม่ทำให้พัง
- **พิสูจน์ว่าเทสต์จับบั๊กเดิมได้จริง** — ใส่บั๊กกลับเข้าไป (ถอด `rememberGeo` ออกจาก `.catch`)
  แล้วเทสต์แดง 2 เคสด้วยข้อความ "the refusal was retried on the next render" แล้วคืนโค้ด
- `curl` จากเครือข่ายออฟฟิศ **ในนาทีเดียวกับที่เบราว์เซอร์ล้มเหลว**: 200 ทั้งสามแบบ —
  curl เปล่า, ใส่ `Origin: https://attendance.tozaiboeki.co.th`, และใส่ UA ของ Chrome พร้อม
  `Referer` ⇒ **Nominatim ไม่ได้ปฏิเสธคำขอแบบที่เบราว์เซอร์ส่ง**

**ยังไม่ได้ตรวจ และตรวจไม่ได้จนกว่าจะ deploy:** ของจริงในเบราว์เซอร์แบบ end-to-end ·
เหตุผล: เว็บจริงตอนนี้เป็น build 136 ซึ่ง**ผมเองถอด `nominatim` ออกจาก CSP ไปแล้ว** ⇒ การฉีด
โค้ด build 137 เข้าไปทดสอบถูก CSP ของหน้านั้นบล็อกตั้งแต่ยังไม่ออกจากเครื่อง (console บอกว่า
"violates the following Content Security Policy directive") ซึ่งตอนแรกผมอ่านผิดเป็นว่ายังโดน 429 ·
และเปิด build 137 จาก `localhost` ก็ล็อกอินไม่ได้ เพราะ backend อนุญาต CORS แค่ 3 origin
ซึ่งผมจะไม่แก้ค่าของ production เพื่อเอามาทดสอบ
⇒ **ห้ามเขียนว่า "แก้แล้วที่อยู่ขึ้น" จนกว่าจะเห็นมันขึ้นบนเว็บจริงหลัง deploy**
