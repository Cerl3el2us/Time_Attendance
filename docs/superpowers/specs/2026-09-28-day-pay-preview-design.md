# แสดงยอดเงินที่จะได้รับในฟอร์มขอ OT / ขอทำงานวันหยุด (Day Pay Preview)

วันที่: 2026-09-28
สถานะ: design — รอ owner review ก่อนทำ implementation plan

## เป้าหมาย

พนักงานที่ทำงานวันหยุดต้องเลือกว่าจะ **รับเป็นเงิน** หรือ **รับเป็นวันลาพักร้อน +1 วัน** แต่ตอนนี้ฟอร์ม
บอกแค่ว่า "แต่ละโหมดจ่ายอะไร" เป็นข้อความ ไม่มีตัวเลข (`refreshHolidayWorkCompHint()`, app.js:16969)
⇒ ตัดสินใจโดยไม่รู้ว่าเงินคือเท่าไหร่

ต้องการ: ใส่ชั่วโมง/เวลาเริ่ม–เลิกแล้ว **เห็นยอดเงินของวันนั้นทันที แจกแจงเป็นรายการ** รวม Early Morning
ถ้ามี เช่น `Early Morning 240 + OT 900 = 1,140` — และที่ฟอร์มวันหยุดให้ **เทียบ 2 ฝั่งพร้อมกัน**

## สถานะปัจจุบัน (ตรวจจากโค้ดจริง commit 240fb42)

| ฟอร์ม | ตอนนี้ | ขาด |
|---|---|---|
| OT ออฟฟิศ (ใส่เวลาเลิกงาน) | `calcOTHours()` app.js:16724 โชว์ชั่วโมง + `≈ ฿xxx` แล้ว | ไม่รวม Early Morning; ใช้ `currentUser.salary` ทั้งที่ฟอร์มอาจเปิดแทนคนอื่น (ดู "บั๊กที่พบ") |

### กฎการจ่ายเงินของวันทำงานวันหยุด (ยืนยันจาก `computePayroll()`)

**เฉพาะโหมด `paid`**
- ค่าเดินทางวันหยุด ฿500/วัน — app.js:12728 (ไม่จ่ายถ้าเป็นวัน Abroad)
- OT ×2 / ×3 จากเวลาเริ่ม–เลิก — app.js:12731-12732

**ได้ทั้ง 2 โหมดเท่ากัน** (ไม่มีเงื่อนไข `compensationMode` ในโค้ด)
- Upcountry ฿240/วัน ถ้ากรอกชื่อสถานที่ — app.js:12623-12626
- Early Morning / Late Night — app.js:12643-12675

**โหมด `annual-leave`** — +1 วันลาพักร้อน แทนค่าเดินทาง + OT

**กันนับซ้ำ**: ถ้าวันนั้นมี holiday-work แบบ `paid` ใบขอ OT แยกของวันเดียวกันจะถูกข้าม — app.js:12719

Early Morning ต้องโผล่เองโดยไม่ต้องแก้โค้ด

## ดีไซน์

### 1. ไม่เขียนสูตรเงินใหม่แม้แต่ข้อเดียว

พรีวิว **ประกอบ** ฟังก์ชันที่ payroll ใช้จริงเท่านั้น ที่เป็นฟังก์ชันร่วมอยู่แล้ว:

| ใช้ทำอะไร | ฟังก์ชัน |
|---|---|
| แปลงเวลาเริ่ม–เลิก → ชั่วโมง ×2/×3 | `splitHolidayWorkOtMinutes()` app.js:1800 |
| แปลงเวลาเลิกงาน → ชั่วโมง ×1.5 | `deriveOfficeOtFromEndTime()` app.js:1834 |
| ชั่วโมง → เงิน (ปัดเศษแบบ payroll) | `otPayFromHourBuckets()` / `addOtHours()` / `accumulateApprovedOtHours()` |
| Early Morning tier → เงิน | `earlyMorningTierFromCheckIn()` + `earlyMorningAllowanceForTier()` |
| คุณสมบัติสแกนเข้าเงื่อนไข EM/LN | `deviceScanQualifiesForEarlyMorning()` / `...ForLateNight()` |
| Late Night tier → เงิน | `lateOutAllowanceForHour()` |
| สิทธิ์ตาม role | `isAllowanceEligible()` |

เหลือกฎที่ยังฝังอยู่ใน `computePayroll()` **2 ตัว** ต้องดึงออกเป็นฟังก์ชันร่วม แล้วให้ `computePayroll()`
เรียกใช้ตัวที่ดึงออกมานั้นด้วย (ไม่ใช่ copy):

1. `holidayTransportForRecord(l, S, abroadDates)` ← จาก app.js:12727-12729
2. `hasUpcountryLocation(l)` ← จาก predicate app.js:12623-12626

**mirror ทั้ง app.js และ server.js** (owner เลือก 2026-09-28) ตามกฎ payroll dual-sync — เป็น pure
extraction ตัวเลขไม่เปลี่ยน แต่ทำให้ 2 ไฟล์ยังเทียบกันบรรทัดต่อบรรทัดได้ ⇒ ต้อง deploy backend ด้วย

### 2. ฟังก์ชันกลาง

```
estimateDayEarnings({ date, user, mode, otEndTime, driverTiers,
                      hwStartTime, hwEndTime, locations, lateOutHour })
  → { lines: [{ key, label, amount, note }], total, earnsLeaveDay, warnings: [] }
```

- `mode` = `'paid'` | `'annual-leave'` (ฟอร์มวันหยุด) หรือ `null` (ฟอร์ม OT ทั้ง 2 แบบ ซึ่งไม่มีโหมด)
- `user` = **เจ้าของฟอร์ม** ไม่ใช่ผู้ที่กำลังเปิดดู (แก้บั๊กด้านล่าง)
- `hourlyRate = user.salary / 30 / 8`
- ทุกบรรทัดถูกกรองด้วย `isAllowanceEligible()` ของ key ที่ตรงกัน — ไม่มีสิทธิ์ = ไม่แสดงบรรทัดนั้น

### 3. OT คิดเป็น "ส่วนเพิ่มจริง" ไม่ใช่ per-record

```
OT ที่ได้เพิ่ม = otPayFromHourBuckets(bucket เดิมทั้งงวด + ใบนี้)
              − otPayFromHourBuckets(bucket เดิมทั้งงวด)
```

payroll รวมชั่วโมงทั้งงวดต่อ multiplier แล้วปัดเศษ **ครั้งเดียว** (app.js:2124-2132) ⇒ คิดแบบ per-record
จะคลาดระดับสตางค์ วิธีนี้ใช้ฟังก์ชันปัดเศษตัวจริง ไม่ใช่ประมาณการ

ผลพลอยได้สำคัญ: ไดรเวอร์ที่มี `guaranteedOT` สูงกว่าชั่วโมงจริงอยู่แล้ว (app.js:12739-12741) จะเห็น
`OT +฿0` ตามความจริง — แบบ per-record จะโชว์เลขหลอกว่าได้เพิ่ม ซึ่งทำให้ตัดสินใจผิด ทั้งที่ฟีเจอร์นี้
มีไว้ช่วยตัดสินใจ

ข้อมูล OT ที่อนุมัติแล้วในงวดอยู่ใน `DATA_LEAVES` ฝั่ง client แล้ว — ส่งเฉพาะตัวเลขชั่วโมงเข้าฟังก์ชัน
pure ไม่ต้องยัด record ปลอมเข้า state

### 4. UI

**ก. ฟอร์มขอทำงานวันหยุด** — 2 การ์ดพร้อมกันใต้ dropdown, การ์ดที่เลือกอยู่ไฮไลต์, อัปเดตทันทีเมื่อแก้
วันที่/เวลา/สถานที่/tier ค่าทำงานดึก:

```
┌ 💰 รับเป็นเงิน ─────────┐  ┌ 🌴 รับเป็นวันลา ───────┐
│ ค่าเดินทางวันหยุด    500 │  │ +1 วันลาพักร้อน         │
│ OT ×2  4 ชม.         800 │  │ 🌅 Early Morning    240 │
│ 🌅 Early Morning     240 │  │ 🏞️ Upcountry        240 │
│ 🏞️ Upcountry         240 │  ├─────────────────────────┤
├──────────────────────────┤  │ รวมเงิน        ฿480     │
│ รวม            ฿1,780    │  │ + วันลา 1 วัน           │
└──────────────────────────┘  └─────────────────────────┘
```

dropdown ยังเป็นตัวกำหนดโหมด (การ์ดเป็นการแสดงผล ไม่ใช่ปุ่มเลือก) — ลด UI ที่ต้องเปลี่ยน

**ข. ฟอร์ม OT ออฟฟิศ** — ขยายบรรทัด `ot-hours-display` เดิมให้แจกแจง:
`4 ชม. ×1.5 = ฿900 + 🌅 Early Morning ฿240 = ฿1,140`

**ค. ฟอร์ม OT ไดรเวอร์** — บล็อกใหม่ใต้ช่องกรอก tier แจกแจงต่อ tier (ชั่วโมง = hours + mins/60 จาก
`ot-hours-15`/`ot-mins-15` ฯลฯ)

### 5. Early Morning — ไม่เดา อ้างข้อมูลที่บันทึกแล้วเท่านั้น

| สถานะของวันนั้น | แสดงอะไร |
|---|---|
| มีสแกนเครื่องเข้าเงื่อนไข | `🌅 ×2 (สแกน 06:12) ฿480` — กำกับเวลาสแกนจริง |
| สแกนผ่านเว็บ/GPS | `🌅 ฿0` + เหตุผล "ต้องสแกนเครื่องที่ออฟฟิศ" |
| role ไม่มีสิทธิ์ | ไม่แสดงบรรทัดนี้เลย |
| วันหยุดที่ยังไม่อนุมัติ holiday-work | แสดงพร้อมข้อความ "ถ้าคำขอนี้ได้รับอนุมัติ" |

### 6. คำเตือนใหม่ที่วันนี้ยังไม่มีในระบบ

ฝั่ง "รับเป็นเงิน" ต้องหัก logic app.js:12719 ออกด้วย **และ** เตือนว่า:
"มีใบขอ OT ของวันนี้อยู่ 3 ชม. — ถ้าเลือกรับเป็นเงิน ใบนั้นจะไม่ถูกนับ"
ตอนนี้พนักงานมองไม่เห็นกับดักนี้เลย

### 7. เคสขอบ

- `salary = 0` หรือไม่มีค่า → ซ่อนเงิน โชว์แค่ชั่วโมง (แบบเดียวกับที่ `calcOTHours()` ทำอยู่)
- วัน Abroad → ไม่มีค่าเดินทางวันหยุด ไม่มี Upcountry
- วัน Company Trip → ไม่จ่ายอะไรเลย
- แก้ไขคำขอเดิม (`editingLeaveId`) → ต้องไม่นับใบตัวเองซ้ำใน bucket เดิม
