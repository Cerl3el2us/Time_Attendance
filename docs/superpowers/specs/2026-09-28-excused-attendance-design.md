# Excused Attendance — วันที่บริษัทผ่อนปรนเป็นรายกรณี

วันที่: 2026-09-28
สถานะ: design — รอ owner review ก่อนทำ implementation plan

## ปัญหา

เวลาเกิดเหตุสุดวิสัยวงกว้าง (น้ำท่วม ฯลฯ) บริษัทผ่อนปรนให้มาสายหรือไม่มาทำงานได้ แต่ระบบยังตัดสินตามกฎเดิม:
สแกนเกินเวลา → ขึ้น "สาย", ไม่สแกนเลย → ขึ้น "ไม่มาทำงาน" ⇒ ประวัติพนักงานมีรอยที่ไม่ใช่ความผิดของเขา

**ไม่ใช้วันประกาศทั้งบริษัท** — owner: "น้ำท่วมไม่ได้ท่วมทุกบ้านพร้อมกัน" บ้านคนหนึ่งท่วม 3 วัน อีกคนไม่ท่วมเลย
⇒ ต้องเป็นรายคน รายวัน case by case

**คุณค่าจริงของฟีเจอร์นี้จึงเป็น 3 ข้อ ไม่ใช่เรื่องปลดล็อกเงินเดือน:**
1. สรุปประจำเดือน/สลิป/รายงาน เลิกนับวันนั้นเป็น "ขาดงาน" และ "มาสาย" (owner ยืนยัน 2026-09-28)
2. ตารางเวลาบันทึก**เหตุผล**ที่ผ่อนปรนไว้ — เปิดดูย้อนหลังยังรู้ว่าเกิดอะไรขึ้น
3. ตอบคำถามที่ค้างในสเปก `2026-09-26-design-decisions.md` บรรทัด 106 ("อะไรนับเป็นขาด? นับแค่ unexcused?")
   ได้ว่าวัน excused ไม่ตัดเบี้ยขยัน — เมื่อไรที่สร้างกฎเบี้ยขยัน

## ดีไซน์

### 1. record

`type: 'excused'`, `status: 'approved'` ทันทีตอนสร้าง (ไม่มี approval route), `userId`, `dateFrom`/`dateTo`,
`reason` (บังคับ — เช่น "น้ำท่วมบ้านพนักงาน"), `createdBy` = MD/บัญชีที่กำหนด
แนบไฟล์ได้ (รูปน้ำท่วม) ด้วยกลไกเดียวกับใบรับรองแพทย์ของลาป่วย

### 2. สถานะวัน — ใช้สถานะที่มีอยู่แล้วให้มากที่สุด (แก้ไข 2026-09-28 หลังสำรวจโค้ด)

แทรกใน `generatePeriodDays()` โซนเดียวกับ company-trip (app.js:5882 / server.js dual-sync):

| กรณี | สถานะที่ตั้ง | เหตุผล |
|---|---|---|
| **มีสแกนแต่สาย** | `present` (แทน `late`) + `excused: true` + `excusedReason` | `lateDays` เลิกนับ แต่ `daysWorked` **ยังนับ** และ whitelist ทุกตัวผ่าน เพราะ `present` อยู่ในลิสต์อยู่แล้ว |
| **ไม่มีสแกนเลย** | `excused` (แทน `absent`) + `excusedReason` | `absentDays` เลิกนับเอง; ไม่กระทบ whitelist เพราะไม่มีสแกน = ไม่มีเบี้ยเลี้ยงให้คิด |

คงเวลาสแกนจริงไว้ทั้งหมด (checkIn/checkOut/source/GPS) — ไม่บิดข้อมูลเวลาแบบ Time Correction

**เหตุผลที่ NOT ใช้ `excused` กับทั้ง 2 กรณี** (ดีไซน์แรกผิด จับได้ตอนสำรวจ): ตัวนับ "วันทำงาน" คือ
`present|late|not-clocked-in|abroad` (app.js:9081, 11803, 12376, **12827 `daysWorked` ที่โชว์บนสลิป**)
⇒ ถ้าวันที่มาสายกลายเป็น `excused` คนที่ฝ่าน้ำมาทำงานจะหายจากวันทำงานของตัวเองบนสลิป

### 3. จุดที่ต้องไล่ให้ครบ

การพลิก `late → present` ทำให้ ripple แทบทั้งหมดหมดไป (present ผ่านทุก whitelist/blacklist อยู่แล้ว)
เหลือที่ต้องตรวจ:

- **สถานะใหม่ `excused` (เฉพาะกรณีไม่มีสแกน)** ต้องเพิ่มใน `statusBadge` map (app.js:9359) และตรวจว่าไม่หลุด
  เข้าไปในตัวนับที่ไม่ควรนับ — `workingDays` (12826) ยังควรนับเป็นวันทำงานของงวด (เป็นวันทำงานที่ได้รับการยกเว้น)
- **ทุกจุดที่อ้าง `'absent'`** (app.js:5944, 5948, 5983, **5994 `treatAsFull` ที่ผูกกับลาบางส่วน**, 9362, 12831
  + คู่แฝด server.js) — ตรวจว่าการเปลี่ยนเป็น `excused` ไม่ทำให้ logic ลาครึ่งวัน/ลาบางส่วนเพี้ยน
- **ธง `excused` ต้องไปถึงการแสดงผล** ทั้งตารางเวลา, หน้าพิมพ์ (9369-9402), การ์ดมือถือ (9288) และรายงาน

### 4. คืนวันลาอัตโนมัติ

ถ้าวันที่ถูกกำหนด excused มีใบลา annual/sick/business ที่อนุมัติแล้วอยู่ → ยกเลิกใบนั้นและคืนโควตา

**กับดักที่ต้องทดสอบเป็นพิเศษ**: memory บันทึกว่า Opus round-3 review เมื่อ 2026-09-25 เจอบั๊กว่าการ
ยกเลิก/เพิกถอน record ไปพัวพันกับ `earnedDayUsedError()` และ carry-forward (record กลายเป็นยกเลิกไม่ได้)
— การคืนวันลาอัตโนมัติวิ่งผ่านเส้นเดียวกัน

**เคสครึ่งวัน**: ใบลาครึ่งวัน/ลาบางส่วนต้องคืนตามหน่วยที่ใช้จริง ไม่ใช่คืนเต็มวัน

### 5. UI

MD/บัญชีเปิดจากแถวของวันในหน้า Attendance ของพนักงานคนนั้น (ที่เดียวกับที่ Quick Fix อยู่) →
เลือกช่วงวัน + กรอกเหตุผล + แนบไฟล์ (ถ้ามี) → บันทึก
ป้ายในตาราง: สถานะใหม่ (ไอคอน + ข้อความ 3 ภาษา) ต้องเพิ่มใน `statusBadge` map (app.js:9359 โซนเดียวกับ
`case 'company-trip'` / `case 'absent'`)

### 6. ไม่แตะ

- นโยบาย `lateDeductPolicy` — คงปิดไว้ ไม่ลบโค้ด (ข้อตกลงที่ 6)
- สูตรเงินเดือนและเบี้ยเลี้ยงทุกตัว
- กฎเบี้ยขยัน — ยังไม่สร้าง (ยังค้างที่ owner) ฟีเจอร์นี้แค่เตรียมข้อมูลให้พร้อม

## การตรวจสอบ

- เทสต์: วัน excused ที่ไม่มีสแกน (ต้องไม่นับ absent), ที่มีสแกนสาย (ต้องไม่นับ late แต่ยังโชว์เวลาจริง),
  คนที่ฝ่าน้ำมาเช้า **ต้องยังได้เบี้ยมาเช้า** (เทสต์ตรงจุดเสี่ยง whitelist), ทำ OT ในวัน excused ต้องได้ OT,
  ช่วงวันที่คร่อมเสาร์-อาทิตย์, วันที่มีใบลาอยู่แล้ว (ต้องคืนโควตา), ใบลาครึ่งวัน, งวดที่ปิดแล้ว (ต้องถูกปฏิเสธ)
- ตรวจ `absentDays`/`lateDays` ที่ปรากฏบน**สลิป Excel** ด้วย ไม่ใช่แค่หน้าเว็บ
