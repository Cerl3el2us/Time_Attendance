## 🔴 การแก้ไข (เฉพาะส่วนที่ยืนยันแล้ว)

**ที่:** `app.js:8010` ในฟังก์ชัน `submitOT()`
```js
const otMultiplier = isPublicHoliday(date) ? 3 : 1.5;
```

**แก้เป็น:**
```js
const dow = new Date(date + 'T12:00:00').getDay();
const otMultiplier = (isPublicHoliday(date) || dow === 0 || dow === 6) ? 3 : 1.5;
```
(ใช้ pattern `new Date(dateStr + 'T12:00:00').getDay()` เหมือนที่ใช้อยู่แล้วใน `computeLateDeductMinutes()`/`generatePeriodDays()` กันปัญหา timezone)

**ยืนยันแล้วว่าเป็นจุดเดียวที่คำนวณ otMultiplier สำหรับ OT พนักงานทั่วไป** (grep `otMultiplier\s*=` ทั้งไฟล์ เจอแค่บรรทัดนี้ที่คำนวณจริง ที่เหลือเป็นแค่ label แสดงผล `l.otMultiplier === 3 ? ...` ที่ `:5427` และ `:6859` — ไม่ต้องแก้เพราะแค่อ่านค่าที่บันทึกไว้แล้วมาโชว์). ครอบคลุมทั้ง submit ใหม่และแก้ไขคำขอเดิม (`editingLeaveId` branch ใช้ตัวแปรเดียวกันนี้ก่อนแยก path)

**FAQ text ไม่ต้องแก้** — ข้อความเดิม (`app.js:10872-10874`, "holiday/weekend OT pays ×3.0" / "วันหยุด/เสาร์-อาทิตย์จ่าย ×3.0") **ถูกต้องอยู่แล้ว** ตรงกับนโยบายที่ user ยืนยัน โค้ดต่างหากที่ต้องตามให้ทัน

## ⚠️ คำถามที่ต้องรายงานกลับ user (ห้ามตัดสินใจเอง — เหมือนเคส T-01)
โค้ดเดิมให้ ×1.5 สำหรับ OT เสาร์-อาทิตย์มาตลอด (ตั้งแต่ feature นี้มีมา) ถ้าเคยมีพนักงานยื่น/ได้รับอนุมัติ OT วันเสาร์-อาทิตย์จริงในอดีต **พวกเขาอาจได้รับเงินขาดไปจากที่ควรได้ (จ่าย 1.5x แทนที่จะเป็น 3x)** — ให้ Sonnet ตรวจสอบ (ผ่าน SSH อ่าน `leaves.json` แบบ read-only ไม่แก้ไขอะไร) ว่ามี record `type:'ot', isDriverOT` ไม่ true, `otMultiplier:1.5` ที่ `dateFrom` ตรงกับวันเสาร์-อาทิตย์จริงหรือไม่ (นับจำนวน ไม่ต้องแก้อะไร) แล้วรายงานตัวเลขกลับมาให้ user ตัดสินใจว่าจะจ่ายชดเชยย้อนหลังไหม
